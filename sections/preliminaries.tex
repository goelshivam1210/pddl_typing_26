\section{Preliminaries}

\subsection{Symbolic Planning}
\subsubsection{Classical Planning with Types}

% We adopt the PDDL planning formalism~\cite{mcdermott1998pddl}, which extends classical STRIPS~\cite{fikes1971strips} with a type hierarchy. A planning domain $D$ consists of a set of predicates $\mathcal{P}$, a set of actions $\mathcal{A}$, and a type hierarchy $\mathcal{T}$. Each type $\tau \in \mathcal{T}$ denotes a set of objects; the hierarchy imposes $\tau_1 \sqsubset \tau_2$ (e.g., $\texttt{eraser} \sqsubset \texttt{tool} \sqsubset \texttt{object}$). Each action $a \in \mathcal{A}$ is defined as $a = \langle \text{pre}(a), \text{add}(a), \text{del}(a) \rangle$ where $\text{pre}(a), \text{add}(a), \text{del}(a) \subseteq \mathcal{P}$, and each parameter of $a$ is constrained to a type $\tau \in \mathcal{T}$. A planning problem $\Pi = (D, O, \sigma, I, G)$ pairs the domain with a set of objects $O$ and a type assignment $\sigma : O \rightarrow \mathcal{T}$. Let $\mathcal{F}$ denote the set of ground atoms obtained by instantiating the predicates $\mathcal{P}$ with objects from $O$. A \emph{state} $s \subseteq \mathcal{F}$ is a set of ground atoms; the initial state $I \subseteq \mathcal{F}$ is one such state, and the goal $G \subseteq \mathcal{F}$ is a set of atoms defining the \emph{goal states} $\{\, s \mid G \subseteq s \,\}$. The type assignment $\sigma$ determines action applicability: an action schema parameterised over type $\tau$ may only be grounded with objects $o$ such that $\sigma(o) \sqsubseteq \tau$.

% A \textit{plan} $\pi$ is a sequence of grounded actions $\langle a_1, \ldots, a_k \rangle$ such that executing the sequence from $I$ satisfies $G$. A symbolic planner takes $\pi$ as input and returns either a valid plan or reports that no plan exists.


We adopt the typed STRIPS fragment of the Planning Domain Definition Language (PDDL)~\cite{mcdermott1998pddl}, which extends classical STRIPS~\cite{fikes1971strips} with typed objects and action parameters. A planning domain $D = \langle \mathcal{P}, \mathcal{A}, \mathcal{T} \rangle$ consists of predicate symbols $\mathcal{P}$, action schemas $\mathcal{A}$, and a finite set of types $\mathcal{T}$. Each action schema $a \in \mathcal{A}$ is a tuple $a = \langle \mathrm{par}(a), \mathrm{pre}(a), \mathrm{add}(a), \mathrm{del}(a) \rangle$, where $\mathrm{par}(a)$ are typed parameters and the remaining components are sets of atoms over those parameters. Preconditions are positive conjunctions, and effects are represented by add and delete lists.

A planning problem $\Pi = \langle D, O, \sigma, I, G \rangle$ consists of a domain $D$, a finite set of objects $O$, a type assignment $\sigma : O \rightarrow \mathcal{T}$, an initial state $I$, and a goal $G$. Let $\mathcal{F}$ be the set of all well-typed ground atoms over $\mathcal{P}$ and $O$. A state $s \subseteq \mathcal{F}$ contains the atoms true in that state, while omitted atoms are false under the closed-world assumption. The initial state $I \subseteq \mathcal{F}$ is a single fully specified state, whereas $G \subseteq \mathcal{F}$ defines the goal-state set $S_G = \{\,s \subseteq \mathcal{F} \mid G \subseteq s\,\}$.

A parameter of type $\tau$ may be grounded with an object $o$ only if $\sigma(o) = \tau$. A well-typed grounded action $a$ is applicable in $s$ if $\mathrm{pre}(a) \subseteq s$, and produces the successor state $\gamma(s,a) = (s \setminus \mathrm{del}(a)) \cup \mathrm{add}(a)$. A plan for $\Pi$ is a finite sequence of well-typed grounded actions $\pi = \langle a_1,\ldots,a_k\rangle$ that are successively applicable and satisfy $G \subseteq \gamma(I,\pi)$. A sound and complete symbolic planner takes $\Pi$ as input and returns a valid plan if one exists, or establishes that no plan exists.

\subsection{Running Example}
Consider the task depicted in Figure~\ref{fig:robot_example}. A robot must clean a blackboard, and has actions $\mathcal{A} = \{\mathtt{pickup}, \mathtt{wipe}\}$, where $\mathtt{wipe}$ is defined to require an object of type \texttt{eraser} applied to an object of type \texttt{blackboard}. Types restrict which objects each action can be grounded over, and every object is assigned a type a priori. We write a type assignment as a set of $\mathit{object}\!:\!\mathit{type}$ pairs.

\emph{Pre-novelty}, the scene contains an eraser, and the type assignment
\[
\sigma = \{\,\mathtt{eraser}\!:\!\texttt{eraser},\; \mathtt{marker}\!:\!\texttt{marker},\; \mathtt{cup}\!:\!\texttt{cup},\; \mathtt{blackboard}\!:\!\texttt{blackboard}\,\}
\]
is sufficient for the goal $\texttt{(clean blackboard)}$: $\mathtt{wipe}$ grounds over the \texttt{eraser}-typed and \texttt{blackboard}-typed objects, and the planner returns a valid plan. This is the working case that novelty at deployment will break in the next subsection.
 

% For example, the \texttt{wipe} action can encode that an object of the type \texttt{eraser} can be used to erase an object of the type \texttt{blackboard}. Each object would also be assigned a type, let us assume that these types correspond to the object names listed in $\mathcal{O}$.

% We consider two ways the the set of object can be generated:  they may be manually added to the problem file, or the problem file might be generated at run time using the robots sensors such as camera. In the case where a hand crafted problem file is available, objects must be annotated with labels that allow the planner to determine which actions can be applied to which objects. This requires a comprehensive list of types, and additionally may not encode different ways of solving the problem apriori. In the other scenario where the problem file is generated from sensor observations - it is important to consider how types can be associated with each object. In the most general sense, a problem file can be generated assigning each object to a generic type, however this would allow for plans like using the `cup` to clean the `blackboard`, which is not reasonable.


\subsection{The Typing Problem}

A \textit{typed domain} $D_t$ uses types to constrain which objects each action can be applied to, reducing the grounded action space and coupling actions only with compatible objects: for example, \texttt{wipe} is grounded only over an $\texttt{eraser}$-typed tool and a $\texttt{blackboard}$-typed surface. Each object is assigned its type a priori --- without reference to the goal that will later be posed --- whether the problem is hand-authored (where an annotation may be incomplete or simply mistaken), constructed at runtime from open-vocabulary perception, or produced by a fixed object-to-type mapping that cannot anticipate every object encountered at deployment. Any of these can leave an object typed such that no action requiring a particular role will accept it. \emph{Post-novelty}, the eraser from our running example is replaced at deployment by a novel object, a cloth, giving the type assignment
\[
\sigma' = \{\,\mathtt{cloth}\!:\!\texttt{cloth},\; \mathtt{marker}\!:\!\texttt{marker},\; \mathtt{cup}\!:\!\texttt{cup},\; \mathtt{blackboard}\!:\!\texttt{blackboard}\,\}.
\]
No object now carries the type \texttt{eraser}, so \texttt{wipe} cannot be grounded and the previously solvable goal becomes unreachable --- even though the \texttt{cloth} could functionally fill the \texttt{eraser} role. Not every object in $O$ requires reassignment --- objects already carrying a type the goal's action chain accepts, or irrelevant to that chain, retain their types under $\sigma'$.

Crucially, the goal $G$ determines which types are required; for example to achieve $\texttt{(clean blackboard)}$, the planner must execute $\texttt{wipe}$, which requires an $\texttt{eraser}$-typed object. Because the goal may be dictated only at runtime, a type assignment that suffices for one goal need not suffice for another: the very same objects and types can be adequate under one task and leave a gap under the next. When $\sigma$ assigns objects to insufficient types, the grounded action space is such that no plan achieving $G$ exists. We call this a \textit{typing gap}, and treat it purely as a property of the type assignment relative to the goal, independent of how it arose. A typing gap is a restricted instance of \emph{model repair}~\cite{bercher2025modelrepair}: the only modification permitted is reassignment of object types, leaving the domain, goal, and initial state untouched.

\subsection{Problem Formulation}
\label{subsec:llm_query}

We query a large language model $L$ to close the typing gap: given a prompt $\rho$ encoding the domain $D$ and problem $\Pi$, $L$ returns a proposed type assignment $\hat{\sigma} : O \rightarrow \mathcal{T}$, expressed as a set of pairs $\{(o, \tau) \mid o \in O,\, \tau \in \mathcal{T}\}$. Because $L$ samples tokens stochastically, with the degree of randomness controlled by a temperature parameter $T \ge 0$ ($T{=}0$ recovers greedy, near-deterministic decoding and larger $T$ increases variability), repeated queries over the same $\rho$ may yield different assignments.

A typing-gap instance falls into one of two cases, and a correct system must handle both. Either a valid substitution exists --- some object in $O$ could plausibly fill the required type, but $\sigma$ fails to reflect it --- in which case the objective is to find an assignment $\hat{\sigma}$ under which the planner returns a plan achieving $G$; or no object in $O$ is a plausible instance of the required type, no valid substitution exists, and the correct behavior is to return no plan. Every strategy in the next section instantiates the same template: an LLM proposes one or more candidate assignments $\hat{\sigma}$, and each is verified by invoking the symbolic planner on $\Pi|_{\hat{\sigma}}$. Because verification is delegated to the planner rather than the LLM, the framework inherits the planner's guarantees relative to the assigned types.

While we retain the planner's formal guarantees, this is not to say the approach is without a trade-off. In exchange for the flexibility to solve problems a rigid planner would declare unsolvable, we give up any guarantee on the \emph{semantic} validity of $\hat{\sigma}$ --- whether a substitution such as \texttt{cloth}-as-\texttt{eraser} is physically warranted. The planner cannot certify this; it is precisely what our experiments serve to measure.
